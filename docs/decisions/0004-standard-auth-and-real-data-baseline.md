# Decision 0004 — 保留标准认证流程并坚持真实行情基线

Status: ACCEPTED

## 背景

HuntAlpha 仍处于开发阶段，但登录、注册和访客入口本身就是未来正式产品的一部分，不应为了开发审查而临时改造成管理员专用入口。

同时，项目已经接入本机富途 OpenD，并需要确保开发、审查和回归看到的市场数据来自真实授权数据源，而不是静态演示值或生成行情。

## 决策

### 1. 保留标准认证流程

前端继续保留并完善：

- 登录；
- 邮箱注册；
- 访客模式；
- Django Session 认证。

不增加管理员专用审查模式，不通过环境开关隐藏或关闭上述正常入口。

Django staff/superuser 仍可作为普通已登录账户使用现有产品入口，但不为其建立独立前端后门或万能登录机制。

### 2. 运行时行情只使用真实数据

对于已经接入的数据：

- 最新价、涨跌幅、开高低等报价来自后端真实行情接口；
- K 线来自富途 OpenD；
- 指标和图表应基于同一真实运行时数据流；
- 不允许静态价格、生成 K 线或演示行情在数据源失败时自动接管页面。

### 3. 数据不可用时明确显示不可用

当 OpenD 未启动、无权限、证券代码不支持或某个市场尚未接入真实数据源时：

- 显示 `—`、行情不可用或暂未接入等明确状态；
- 不伪造价格、涨跌幅、OHLC、指数或历史行情；
- 可以保留市场和证券代码/名称作为导航清单。

### 4. 当前开发数据基线

当前本地运行时行情入口为富途 OpenD `127.0.0.1:11111`。

后续涉及行情、图表、公式计算和指标验证的开发任务，除明确标注为离线回归/校准测试外，应优先使用真实授权数据进行验证。

## 后果

- 开发阶段看到的认证流程与未来产品方向保持一致，避免以后再做一次反向恢复。
- OpenD 断开时页面可能出现空行情或错误提示，这是预期行为，优于展示假数据。
- 当前顶部市场指数若没有真实来源，继续显示“暂未接入”，后续单独接入真实指数源。
- 生产环境的 CSRF、Cookie、HTTPS、邮件、数据库和正式账户安全策略仍需独立任务处理。
