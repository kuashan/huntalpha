# Decision 0003 — 开发阶段临时管理员审查入口与真实数据原则

Status: SUPERSEDED

Superseded by: `0004-standard-auth-and-real-data-baseline.md`

## 背景

HuntAlpha 当前仍处于开发阶段。前端已经有正式产品方向上的登录、注册和访客入口，这些入口需要保留，因为后续正式网站仍会继续完善和使用。

当时的目标是让项目所有者能够稳定进入前端审查功能，并让开发、校准和回归尽量基于真实授权数据。项目所有者尚未创建普通注册账户，以访客模式进入时又无法看到完整指标，因此曾考虑在现有入口之外增加一个仅用于开发审查的临时管理员入口。同时，部分前端列表、市场摘要和展示价格仍含静态/演示值，而 K 线运行时已经通过本机富途 OpenD 获取真实授权行情。

## 当时的决策

### 1. 保留现有登录、注册和访客入口

现有前端登录、注册、访客模式都继续保留，不因开发审查需求删除、隐藏或停用。

- 不改变现有普通用户登录流程的产品方向。
- 不删除现有注册入口。
- 不删除现有访客入口。
- 后续正式上线时继续迭代这些入口，而不是从管理员模式演化出正式用户体系。

### 2. 开发阶段额外增加“临时管理员审查入口”

在现有登录/注册/访客入口之外，开发环境额外提供一个独立的管理员审查入口，用于项目所有者查看完整功能和指标。

- 管理员审查入口只接受 Django `is_staff` / `is_superuser` 账户。
- 不在前端或 GitHub 中硬编码管理员用户名、邮箱或密码。
- 使用 Django 现有账户、密码校验和 Session 机制。
- 管理员凭据只保存在本地数据库/本地环境中，不进入 GitHub。
- 普通登录、注册和访客接口保持原有行为，不因为管理员入口而被限制。
- 管理员审查入口必须由明确的开发环境配置控制，并且默认关闭或仅在开发配置下开启。
- 该入口属于临时开发工具，正式网站开发完成并准备上线时可以整体删除，不得成为生产后门。

### 3. 管理员权限必须由服务端判断

管理员身份不能只靠前端按钮或前端字段判断。

- 服务端必须验证登录成功后的用户确实为 `is_staff` 或 `is_superuser`。
- 普通账户即使直接调用管理员登录接口，也不能以管理员审查身份进入。
- 不创建免密码、万能密码、自动登录或固定开发密码。

### 4. 开发和审查坚持真实数据优先

对于已经有授权数据源的市场和功能：

- 运行时行情必须来自真实授权数据源；当前优先使用本机富途 OpenD。
- 不得在 OpenD 失败时自动回退到生成 K 线、静态价格或伪造行情。
- 请求失败时应明确显示“行情不可用/数据源未连接”等状态。
- 离线通达信样本只能用于校准与自动回归，不能伪装成网页实时行情。

### 5. 不支持的数据必须明确显示不可用

如果某个市场、证券或数据项当前没有真实授权来源：

- 可以保留入口用于后续开发；
- 但不得显示模拟价格、模拟涨跌幅或生成历史行情；
- 应显示“暂未接入真实数据”或等价提示。

### 6. 当前真实数据基线

当前 Django 后端已通过 `127.0.0.1:11111` 连接富途 OpenD，并为支持的证券提供真实快照与历史 K 线。

后续涉及行情、指标、图表和校准的开发任务，除 task 明确说明为离线回归测试外，均应以该真实数据流作为运行时基线。

## 被取代的原因

- 项目所有者决定恢复并保留原有完整的登录、注册和访客流程，不再使用管理员专用审查模式。
- 管理员专用审查模式及其环境开关、前端入口和运行时限制不作为当前产品功能；Decision 0004 记录当前有效基线。
- 真实数据原则继续保留，OpenD 未连接时显示空数据或错误状态，优于展示假数据。
- 前端继续移除静态/演示行情值；正式上线前仍需完善正式用户注册、登录、权限、CSRF 和安全策略。
