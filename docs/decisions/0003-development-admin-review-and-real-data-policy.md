# Decision 0003 — 开发阶段管理员审查与真实数据原则

Status: SUPERSEDED

Superseded by: `0004-standard-auth-and-real-data-baseline.md`

## 背景

HuntAlpha 当前仍处于开发阶段。前端每次打开都会进入完整的登录/注册/访客流程，这会增加产品审查成本；同时当前部分前端列表、市场摘要和展示价格仍含静态/演示值，而 K 线运行时已经通过本机富途 OpenD 获取真实授权行情。

项目当时的目标是让项目所有者能够稳定进入前端审查功能，并让开发、校准和回归尽量基于真实授权数据进行。

## 当时的决策

### 1. 开发阶段采用“管理员审查模式”

在正式用户系统上线前，前端审查入口只允许已有 Django 管理员/工作人员账户进入。

- 不在前端或 GitHub 中硬编码管理员用户名、邮箱或密码。
- 使用 Django 现有账户与 Session 机制。
- 管理员凭据只保存在本地数据库/本地环境中，不进入 GitHub。
- 开发阶段前端可以隐藏或关闭公开注册与访客入口。
- 该模式必须通过明确的开发环境配置控制，不能成为未来生产环境的永久后门。

### 2. 开发和审查坚持真实数据优先

对于已经有授权数据源的市场和功能：

- 运行时行情必须来自真实授权数据源；当前优先使用本机富途 OpenD。
- 不得在 OpenD 失败时自动回退到生成 K 线、静态价格或伪造行情。
- 请求失败时应明确显示“行情不可用/数据源未连接”等状态。
- 离线通达信样本只能用于校准与自动回归，不能伪装成网页实时行情。

### 3. 不支持的数据必须明确显示不可用

如果某个市场、证券或数据项当前没有真实授权来源：

- 可以保留入口用于后续开发；
- 但不得显示模拟价格、模拟涨跌幅或生成历史行情；
- 应显示“暂未接入真实数据”或等价提示。

### 4. 当前真实数据基线

当前 Django 后端已通过 `127.0.0.1:11111` 连接富途 OpenD，并为支持的证券提供真实快照与历史 K 线。

后续涉及行情、指标、图表和校准的开发任务，除 task 明确说明为离线回归测试外，均应以该真实数据流作为运行时基线。

## 被取代的原因

项目所有者随后决定恢复并保留原有完整的登录、注册和访客流程，不再使用管理员专用审查模式。真实数据原则继续保留，并由 Decision 0004 作为当前有效决策记录。
