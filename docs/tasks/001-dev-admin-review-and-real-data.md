# Task 001 — 开发阶段临时管理员审查入口与真实行情清理

Status: READY_FOR_CODEX

## 背景

HuntAlpha 仍处于开发阶段。当前前端已有登录、注册和访客模式，这些属于未来正式产品流程，必须保留。

当前项目所有者尚未创建普通注册账户，而访客模式无法查看完整指标，因此需要在现有入口之外增加一个可在后续上线前删除的“临时管理员审查入口”。

同时，部分前端展示数据仍来自 `frontend/src/data/marketData.js` 中的静态/演示值。Django 后端已经通过本机富途 OpenD `127.0.0.1:11111` 提供真实快照和历史 K 线，`MarketChart.vue` 的 K 线也已经走 `/api/kline/`，并且失败时不会生成假 K 线。

本任务依据：`docs/decisions/0003-development-admin-review-and-real-data-policy.md`。

## 目标

1. 保留现有登录、注册、访客入口和原有行为。
2. 在现有入口之外，额外增加一个仅开发阶段使用的临时管理员审查登录，用于项目所有者查看完整指标和功能。
3. 清除当前前端可见的静态/演示行情价格和涨跌幅；对于富途 OpenD 支持的数据，全部使用真实运行时数据。
4. OpenD 或真实数据不可用时明确显示不可用，不允许回退到模拟/生成行情。

## 范围

### 必须做

- 保留当前普通登录入口。
- 保留当前注册入口。
- 保留当前访客入口。
- 在现有认证页面额外增加“管理员审查登录”入口/模式。
- 管理员审查登录只允许 Django `is_staff` 或 `is_superuser` 账户通过。
- 普通非 staff/superuser 账户即使知道管理员登录接口，也不能以管理员审查身份进入。
- 复用 Django 现有账户、密码校验和 Session，不创建硬编码管理员凭据。
- 临时管理员入口由开发环境配置控制，默认必须安全，未来可以整体关闭/删除，不得形成生产后门。
- 管理员登录成功后拥有完整前端审查权限，不按访客限制隐藏指标。
- 当前支持证券的前端最新价、涨跌幅、开高低等展示改为调用后端真实行情接口 `/api/quote/<code>/`。
- 保留现有 `/api/kline/<code>/` 的真实 OpenD K 线数据流，不增加任何演示回退。
- 清理/停止使用 `frontend/src/data/marketData.js` 中的硬编码价格、涨跌幅和生成行情作为网页运行时数据。
- 如果市场/证券当前没有真实数据源，显示明确的“暂未接入真实数据/行情不可用”，不得显示模拟数字。
- 页面上的市场摘要如果目前只有静态值：要么接入已经确认可从 OpenD 获取的真实指数/市场数据，要么先显示不可用；不得保留静态数字冒充实时数据。
- 保留证券代码/名称的静态导航清单是允许的，但价格、涨跌、OHLC、历史行情等市场数据必须来自真实数据源。
- 为临时管理员审查登录和真实行情展示增加相关自动测试。

### 不做

- 不删除、隐藏、禁用现有普通登录、注册、访客入口。
- 不改变普通用户注册/登录/访客流程的现有产品逻辑，除非为兼容新增管理员入口所必需。
- 不在本任务中完成正式用户注册/邮箱验证/找回密码体系。
- 不在本任务中完成生产部署、PostgreSQL、HTTPS、支付或邮件服务。
- 不把管理员用户名、邮箱、密码写入代码、`.env.example` 或 GitHub。
- 不创建自动登录、免密码后门、固定万能密码或“开发密码”。
- 不为了补齐数据而抓取未经授权的网站行情。
- 不把离线通达信校准样本当成网页实时行情。
- 不对公式引擎做与本任务无关的重构。

## 技术与安全约束

- 遵守根目录 `AGENTS.md`。
- 不提交任何秘密信息、本地数据库、日志或用户数据。
- 不进行任务范围之外的重构。
- 管理员身份由 Django 服务端的 `is_staff` / `is_superuser` 判断；不要在前端自行伪造管理员角色。
- 管理员审查入口必须有独立的服务端权限校验，不能仅靠隐藏/显示前端按钮实现。
- Django Session 继续作为本地开发阶段认证基础。
- 现有普通登录、注册、访客接口继续保持可用。
- 不因为 OpenD 失败而生成、缓存或展示假价格。
- 对真实数据接口错误应有清晰可见的 UI 状态。

## 实现要求

1. 增加开发审查模式开关，例如环境变量形式；名称可按现有风格确定，但必须记录在 `.env.example`，且不得包含真实凭据。
2. 在 `AuthGate.vue` 的现有登录/注册/访客流程旁增加一个清晰独立的“管理员审查登录”入口；不能替换现有入口。
3. 建议为管理员审查登录使用独立后端接口或等价的服务端明确校验路径；登录成功前必须确认用户为 `is_staff` / `is_superuser`。
4. 普通登录、注册、访客继续按现有流程工作；管理员入口只是额外的临时开发工具。
5. 管理员审查模式关闭时，临时管理员入口不显示或不可用，但普通登录/注册/访客不受影响。
6. 管理员登录成功后正常建立 Django Session，并能进入完整终端，不受访客指标限制。
7. 如果当前本地数据库没有可用管理员账户，不要创建硬编码账户；只在完成报告中明确说明需要使用 `python manage.py createsuperuser` 创建本地管理员，并由用户自行输入凭据。
8. 进入终端后，对当前选择证券调用真实 `/api/quote/`，并将最新价、涨跌幅、开、高、低以及数据源状态用于页面展示。
9. `marketData.js` 可继续保存市场与证券代码/名称清单，但移除或停止消费其中的硬编码实时行情字段；`makeBars()` 不得再作为网页运行时行情后备。
10. 市场顶部摘要不得继续展示静态行情数字。没有真实来源时显示 `—` / `暂未接入`；只有确认来自真实接口的数据才能展示数值。
11. OpenD 未启动、无权限、代码不支持或接口返回错误时，前端显示明确错误/不可用状态，K 线与报价均不得伪造。
12. 保持当前 `MarketChart.vue` 真实 `/api/kline/` 逻辑及“不回退假 K 线”的原则。
13. 完成后用至少一个 OpenD 当前可用证券进行人工验证，例如 `SH.600519`；报告实际使用的代码和数据源，但不要把本地账号或敏感信息写入报告。
