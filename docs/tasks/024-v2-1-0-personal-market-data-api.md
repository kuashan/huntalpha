## 一、已确认的产品范围（用户决定）

1. SiftAlpha.com 四个市场中，仅以下 **三个股票市场** 允许登录用户自行接入具备相应权限的行情 API：
   - 沪深 A 股（`cn`）
   - 美股（`us`）
   - 港股（`hk`）
2. 加密货币（`crypto`）**排除在本任务之外**，继续采用当前系统数据源及策略，不增加个人 API 入口。
3. 在 **个人中心新增「行情 API」** 页面，提供个人供应商凭证连接、测试/验证、停用或删除，以及三个市场各自独立的来源选择。
4. 每个股票市场提供 **「系统行情 / 用户行情」独立选择开关**：
   - 未配置/未通过测试的个人 API：仅使用管理员已有系统行情；不可虚假标记为「用户行情已连接」。
   - 用户成功连接并通过适用市场的权限测试后，该市场**默认优先使用用户行情**；用户可随时主动改选「系统行情」。
   - 每个市场独立配置；同一账户可以 A 股用个人、港股/美股用系统，或其他任意独立组合。
   - 禁用/删除个人 API 后对应市场恢复系统行情，不影响其他市场和其他用户。
5. **「用户行情」替换的是整套行情输入，而非仅最新价格**：
   - 同一账户+市场下，实时报价、历史 K 线、OHLCV/成交量，以及依赖行情数据的图表与技术指标，必须采用一致的已选供应商和复权口径。
   - 切换来源时清除/失效该账户对应市场的旧来源实时状态、缓存视图，并重新获取新供应商完整历史 K 线，再据此刷新指标；不能拼接不同供应商的历史/实时 K 线。
   - 若供应商不支持某周期或不具备相应历史数据权限，应明确显示功能不可用，不得混入另一供应商数据充当同一序列。
   - 用户显式选择个人行情后，连接失败、供应商限流或权限不足时要显示真实错误，**不得悄悄回退或混接系统来源**；由用户主动切换回系统行情。

## 二、必要实现与安全边界（未来开发前必须核查）

- **账户级隔离**：个人凭证、来源选择、历史 K 线缓存、报价、实时订阅/流、形成中的 bar、服务端指标计算输入均按账户+市场+供应商/凭证版本隔离。不得发生 A 用户带来的行情被 B 用户读取、缓存命中或共享订阅的情况。
- **服务端凭证安全**：凭证仅经已登录账户的后端 HTTPS/CSRF 流程提交；使用独立的静态密钥体系加密保存、具备替换/撤销能力；浏览器、日志和 API 响应不得回显完整 Key。任何有读取凭证能力的服务必须执行最小权限与限流。
- **真实权限和延迟**：连接测试要区分 API 凭证有效、具体市场/历史周期的授权、真实/延时行情状态。不能将「轮询 60 秒」或「配置成功」宣称为有权使用实时行情；必须依据供应商返回的能力和许可。
- **复权/日期/行情一致性**：保存/输出明确的前复权、后复权、不复权标记和交易所时区、市场日历；不能因新 API 重现跨来源复权偏差或重复日线。
- **指标范围**：现有图表、普通技术指标、私人通达信/缠论等以用户选定的同一行情窗口计算，**不改原算法**。技术动能须沿用原六维算法和行情输入一致性约束。
- **明确排除**：恐慌与贪婪目前由独立上游分析服务产生、AI 分析也有独立服务；第一版不得假定它们自动改用用户 API，不为迎合本任务重写其评分算法。市场概览、榜单、全市场目录/搜索暂保留系统供应商。
- **法律和使用条款**：用户提供 API Key 不自动授予 SiftAlpha 对外再分发权限。上线前逐供应商核查用户私用、服务器代理、商业使用、来源标注及授权边界。
- **不开放任意网络地址**：首版基于获批准的供应商白名单和受控适配器，不开放任意 URL/自带 Python 脚本；后续如讨论自建 HTTP API，须单独评估 SSRF、内网/元数据访问与响应校验安全。
- **供应商选择未最终批准**：Longbridge 与 Tushare 已有部分适配代码，适合作为候选，但**用户尚未最终确认首批供应商、市场实时权限和费用/许可条件**。Massive、IBKR、自建 API 不自动纳入本任务。
- **多租户适配审计**：现有行情选择是管理员的全站设置，`MarketDataCache` 为 `market+symbol+period+provider` 维度，`RealtimeRegistry` 为共享订阅；现有 Tushare/Longbridge 的 SDK 凭证接入假设需要确认是否支持多用户私密凭证和并发隔离。
- **生产数据保护**：未来涉及数据库字段/迁移，须遵守受控备份、SHA256/SQLite 完整性、孤立迁移预演与回滚；不得改动会员、自选、个人指标与私人公式、Crypto/其他项目或 Cloudflare。

## 三、未来研发时建议的最小验收标准

1. 两个不同账号使用不同 API，不相互泄露凭证、K 线、订阅或缓存；未连接账号完全保留原系统来源。
2. 三市场开关独立、跨会话保留；连接成功后的默认个人优先、主动切换、删除后回系统规则均正确。
3. 对一个股票的实时报价、历史 K 线和可用的指标计算验证同源/同复权；切换后不存在旧来源混入。
4. 真实权限不足、延时、断连、被限流、不支持周期时明确提示，不伪造实时或悄悄降级。
5. 证明确保 Crypto 数据管线、第三方独立评分服务及现有公共行情来源不变。
