# Task 022 — V2.0.1 行情供应商交易日时间戳一致性

## 用户反馈（2026-10-24）

管理员在 Yahoo Finance 与腾讯财经之间切换 A 股来源后，焦点科技 `SZ.002315` 日线图出现两根同属 2026-10-23 的 K 线。只读查询证实 Yahoo 标记为北京时间 09:30，腾讯标记为北京时间 00:00；两边的交易日与实际 OHLCV 相同。V2.0.0 正式 Commit `16e15740e0c492dc26170781ce521a16b867051f`。

## 所有已接入来源检查范围

- Yahoo Finance：中、美、港；返回按市场真实行情时间戳；日/周/月需按交易所日期统一。
- 腾讯财经：中、港、美；历史日期使用交易所当地零点；与 Yahoo 原时间戳不同。
- Tushare：A 股；修复未带时区的备用日期解析按 UTC 的漏洞。
- Longbridge：中、美、港；修复 naive datetime 在服务器本地时区解释的漏洞。
- Coinbase：加密市场 UTC，原始聚合逻辑已有规范；通过统一出口回归，不调整其交易逻辑。
- 旧 Futu OpenD 仅供显式兼容，不恢复为默认运行 Provider。

## V2.0.1 定点修复

1. 在统一行情契约 `MarketDataFetch.from_payload` 正规化日线、周线、月线的**交易所本地日/ISO 周一/月初**时间锚点；分钟/小时 K 线保持精确交易时间不变。
2. 同一供应商若给出重复周期记录，按该供应商返回的最近记录保留**整根** OHLCV，不跨供应商拼接或均摊。
3. 实时 `RealtimeStateStore` 使用相同时间规范；后台来源更换时清除该证券/周期状态中的原供应商 `current_bar` 和 `last_closed_bar`，不产生跨来源“已收盘”假信号。
4. 前端维护已加载历史数据的来源身份。检测到实时来源更换，重新获取新供应商**完整历史窗口**并替换图表及指标计算输入，保留单一行情源，不将短尾部合并旧历史。
5. 图表日期按证券所属交易所的时区显示，而非浏览器设备所在时区。
6. 股票公式快照叠加必须检查供应商身份，杜绝旧行情源当前 bar 叠加新来源历史。
7. 回归覆盖 Yahoo ↔ 腾讯双向切换、中港美加密、夏令时、年/周/月交界、分钟周期不变、状态清理、原 OHLCV 不被修改及网站版本契约。

## 不改变的边界

- 不改变行情商提供的 OHLCV、复权选择、历史数据来源优先级或评分算法。
- 不改私人通达信公式、原版恐贪和技术动能算法，不迁移数据库。
- 不影响会员、自选、工作区、其他容器和 Cloudflare。
- 独立修复分支：`fix/web-v2-0-1-market-calendar-timestamps`；必须先 PR 审查与必要测试。正式分支通过受控合并后才能触发 ARM64 正式构建；生产部署须用户另行授权真实镜像 Digest。
