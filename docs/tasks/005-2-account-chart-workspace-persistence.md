# Task 005.2 — 账号级图表指标与副图高度持久化

状态：`IMPLEMENTED / PENDING_REVIEW`；不代表已合并或部署。

## 用户确认的唯一范围

- 每个真实登录账号保存一套全局指标配置；所有市场、股票、K 线周期共用，维持现有切换行为。
- 保存主图、副图指标的代码与顺序；副图最多 3 个，保存各副图高度。
- 指标增删、副图拖动结束后自动延时保存；下次登录/换设备恢复。
- 显示所存配置时由服务端再次校验当前权限、是否已启用；PRO 降级 FREE 时**永久删除**不再允许的指标配置，恢复 PRO 不自动复活。
- 访客不向服务器存储。第一次启用不迁移旧浏览器 localStorage 的副图高度，新用户没有记录时使用默认高度。
- 网络错误不写空配置覆盖已保存的数据，不删除用户当前页面设置。
- 只存指标代码/顺序/高度，不存行情、K 线、公式源、计算结果、画线、参数、缩放或最近查看证券。

## 工程边界

- 以冻结 V1.0.0 `924d6811d1eb3e22daff23f6bd3e941746f12884` 为起点，独立分支，目标 `release/siftalpha-web-v1`。
- 数据库迁移仅**新建**与用户 OneToOne 绑定的 ChartWorkspace 表，不改既有 AccountProfile、AccountMembership、WatchlistEntry 或 Formula 表。
- GET 读取当前账号配置并清理失效代码；PUT 使用 JSON + Django 会话/CSRF，服务端检查指标位置、会员权限、启用状态、重复代码和高度范围。
- 正常管理后台更改会员级别时清理配置；绕过 model.save 的批量更新通过下次读写的服务端权限校验清理。
- 不修改现有 XMA、CHANLUN、通达信、Coinbase、图表行情计算及会员判定算法。
- 不创建指标模板、多个工作区、画线/筹码峰或计费功能。
- 任何新版本正式发布都遵守 Issue #48 的版本升级规则；本 PR 不构建、不部署、不执行真实数据库迁移。
